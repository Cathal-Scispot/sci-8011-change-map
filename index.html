SCI-8011 Change Map

API keys can now be read only, read and write, or full. This page shows every file the change touches across the three repos and how they connect, so all four of us can review the whole change from the same picture.

The change in four lines

Keys get a modeRead only, read and write, or full, stored in the existing API_KEY_ROLE table. Old keys with no row stay full.
Endpoints declare a scopeOne of four on each endpoint with @RequiresScope: READ, WRITE, DELETE, FULL. FULL is about the key, not the user's role.
One check, after routingApiKeyScopeInterceptor compares the two. Only requests that carry an API key are scope checked. Web app sessions aren't, though their request body is still scanned for a key.
An off switchAPI_KEY_SCOPES_ENABLED=false on a deployment makes every key full again with no code change. Roles stay stored.

Review the final diff of each PR, not commit by commit. The first four backend commits are an earlier attempt that guessed permissions from words in the URL; it was replaced.

6 · Where to push hardest

  1. Any path where an API key reaches a controller without going through the interceptor.
  2. Any field other than apiKey, Bearer, or a marked token that an endpoint reads a key from.
  3. The level choices: folder lock and unlock and smart-app publish and rollback are FULL by choice.
  4. Main app impact: the interceptor runs on every request and scans a JSON body once.
  5. Whether "one annotation, enforced by the build test" works for the team.

7 · Known limits in this version

  • Who can mint a full key is enforced only in the UI (All is shown to super admins only). The backend accepts OPEN_API_FULL from any signed-in user. Per-user limits come in the next version.
  • The legacy image service and the file endpoints on new.scispot.io are separate services and don't check scopes.
  • A revoked key sent in a different letter case can work for up to 5 minutes, at its original level only.
  • MCP may treat a revoked key as valid for up to 10 minutes; the backend refuses its calls straight away.
  • GET /labspace/get?key= reads a key the check doesn't see. It is a read.
  • Glue requests with no key still identify the customer from source alone. That was there before this change and has its own ticket.
